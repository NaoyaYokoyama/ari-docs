# TL0003 開発支援（Claude Code のハーネス）

## 1. 概要

| 項目 | 値 |
|---|---|
| 目的 | AI（Claude Code）が仕様を守り、壊れたコードのまま作業を終えないようにする仕組み（ハーネス）を説明する |
| 対象 OS | Linux（`verify.sh` は bash） |
| 検証した環境 | Fedora 44、Claude Code 2.1 |

## 2. 構成

| ファイル | 役割 |
|---|---|
| `CLAUDE.md` | AI が毎回読む、構成・検証コマンド・仕様の要点・作業ルール |
| `docs/` | 設計書。書き方は `docs/00_概要/0090_ドキュメントルール.md` |
| `.claude/settings.json` | 作業終了時（Stop）の自動チェックと、確認なしで実行してよいコマンドの設定 |
| `.claude/hooks/verify.sh` | 作業終了時の自動チェックの本体 |
| `.claude/.verify-cache` | 前回チェックに成功したときのコードの状態（git 管理外） |

## 3. 作業終了時の自動チェック

AI が作業を終えるたびに `.claude/hooks/verify.sh` が実行され、次をチェックする。1 つでも失敗すると、エラーの内容を付けて AI に差し戻す。

| 対象 | コマンド | 合格の条件 |
|---|---|---|
| フロントエンド | `cd front && npx tsc -b` | 型エラーが無い |
| フロントエンド | `cd front && npx eslint src` | lint エラーが無い |
| バックエンド | `cd back && cargo build` | エラーと警告が無い |
| デスクトップアプリ | `cd desktop/src-tauri && cargo build` | エラーと警告が無い（バックエンドをライブラリとして使うため、バックエンドの変更で壊れないかも確かめる） |

- 前回成功したときから `front/`・`back/`・`desktop/` が変わっていなければ、チェックを省略する
- 差し戻されて再開した作業ではチェックしない（チェックと差し戻しが繰り返されるのを防ぐため）

手作業で実行するときは、リポジトリのルートで次を実行する。

```bash
.claude/hooks/verify.sh < /dev/null
```

## 4. 設計書の確認

設計書は Markdown ビューア（FN0801、ヘッダーの「Docs」）で読む。ドキュメントルールに沿っているか（id とファイル名の一致など）を警告として表示する。
