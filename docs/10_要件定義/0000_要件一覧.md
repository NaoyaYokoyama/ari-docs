# 0000_要件一覧 要件一覧

まだ設計書（機能要件など）に反映していない要望・課題の一覧。「何を作るか」だけを書く。要求元・優先度・状態などの管理情報は [課題一覧](0090_課題一覧.md) で管理する。

- ID は「RQ0501」の形式。先頭 2 桁は区分（ドキュメントルール 3 章）で、関連する機能要件の区分に揃える。後ろ 2 桁は区分内の連番
- 設計書に反映した要件は、この一覧と課題一覧の両方から削除する（反映先の決定事項に記録が残るため）

## 要件一覧

|ID|概要|詳細|関連|
|---|---|---|---|
|RQ0001|共有モード対応の残り|共有モードの基本（共有サーバーの起動、デスクトップアプリからの接続、ログイン、管理者によるユーザー管理）は対応済み（FN0101・FN0102・FN0002・OP0007）。残りの検討事項は下の「共有モード対応の検討事項」を参照。|FN0101, FN0102|
|RQ0304|共有フォルダの選択|作業フォルダの選択で「新しいフォルダを作る」か「既存の共有フォルダを選ぶ」かを選べるようにする（現行の作業フォルダの変更 FN0002 は、`.ari-docs/` があるフォルダを選ぶとそのデータを使う）。共有フォルダは ari-docs の管理用フォルダ（`.ari-docs/` を想定）があるものだけ選べる。注意: 共有フォルダ上の SQLite に複数の PC から同時に書き込むと DB が壊れるおそれがあるため、運用の制限か共有モード（RQ0001）との使い分けを決める必要がある。|FN0301|

## 共有モード対応の検討事項（RQ0001）

対応済みのものは表から除いた（セッションの保存と期限、ログインのロック、HTTPS、ファイルを開く・ダウンロード、Wiki の最終更新者と同時編集の確認、ログインとログアウト、ユーザー登録、パスワード変更の検証、パスワードをログに出さないこと、ノード操作の API の認証、ヘッダーの表示名とログアウト、待ち受けアドレス、デスクトップアプリからの接続）。

| 分類 | 検討事項 | 現行のコードの状態 |
|---|---|---|
| 認証 | パスワードの有効期限 | なし（長さだけ確認。FN0102-BR05） |
| 認可 | 管理者・利用者の切り替え | 登録時にだけ決められる（FN0102） |
| 認可 | 権限（`role` テーブル）の使い方 | テーブルのみで未使用。権限は `user.role_id`（FN0102） |
| 画面 | フォルダ一覧に「状態」「更新者」の列 | 共有モードのとき表示する実装あり（値は固定） |
| 機能 | 同時に編集している人を、編集中に知らせる | 保存のときに確かめるだけ（FN0501-BR10） |
| 非機能 | 証明書の配布・更新 | HTTPS は設定で使える（FN0101-BR14）。証明書の用意は運用（OP0007） |
| 非機能 | ブラウザからの利用 | 不可（画面はデスクトップアプリだけが持つ。CORS もアプリと開発用だけを許可） |
| 非機能 | 同時接続数・応答時間・バックアップ | 未定 |
