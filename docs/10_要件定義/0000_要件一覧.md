# 0000_要件一覧 要件一覧

まだ設計書（機能要件など）に反映していない要望・課題の一覧。「何を作るか」だけを書く。要求元・優先度・状態などの管理情報は [課題一覧](0090_課題一覧.md) で管理する。

- ID は「RQ0501」の形式。先頭 2 桁は区分（ドキュメントルール 3 章）で、関連する機能要件の区分に揃える。後ろ 2 桁は区分内の連番
- 設計書に反映した要件は、この一覧と課題一覧の両方から削除する（反映先の決定事項に記録が残るため）

## 要件一覧

|ID|概要|詳細|関連|
|---|---|---|---|
|RQ0001|共有モード対応の残り|共有モードの基本（共有サーバーの起動、デスクトップアプリからの接続、ログイン、管理者によるユーザー管理）は対応済み（FN0101・FN0102・FN0002・OP0007）。残りの検討事項は下の「共有モード対応の検討事項」を参照。|FN0101, FN0102|

## 共有モード対応の検討事項（RQ0001）

対応済みのものは表から除いた（パスワードの有効期限は設けない（FN0101）、管理者・利用者の切り替え（FN0102-BR10）、セッションの保存と期限、ログインのロック、HTTPS、ファイルを開く・ダウンロード、Wiki の最終更新者と同時編集の確認、同時に編集している人のお知らせ（FN0501-BR11）、Folder の「説明」（FN0301-BR33）と「更新者」（FN0301-BR34）、権限（`role` テーブルは消し、管理者と利用者・利用者に付ける許可にした。FN0102-BR11）、管理者の PC（FN0102-BR12）、ログインとログアウト、ユーザー登録、パスワード変更の検証、パスワードをログに出さないこと、ノード操作の API の認証、ヘッダーの表示名とログアウト、待ち受けアドレス、デスクトップアプリからの接続）。

| 分類 | 検討事項 | 現行のコードの状態 |
|---|---|---|
| 非機能 | 証明書の配布・更新 | HTTPS は設定で使える（FN0101-BR14）。証明書の用意は運用（OP0007） |
| 非機能 | ブラウザからの利用 | 不可（画面はデスクトップアプリだけが持つ。CORS もアプリと開発用だけを許可） |
| 非機能 | 同時接続数・応答時間 | 当面の規模は 20 人・1 万ファイルまで（2026-11-23 のユーザーの判断）。1 万ファイルで確かめた（開発用のビルドで、何もしないときの CPU は 1 分あたり約 0.3 秒、最初の取り込み約 2 分、ホームの検索・探して開くは 0.1 秒未満。0020_非機能要件）。それより大きくするときは測り直す |
