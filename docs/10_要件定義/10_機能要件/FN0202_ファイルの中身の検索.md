# FN0202 ファイルの中身の検索

## 1. 概要

ホームの検索（FN0201）で、ファイル（ノード）の名前だけでなく中身でも探せるようにする。主な目的は Excel・PDF などの業務ファイルを探すこと。

検索のたびにファイルを読むと遅いため、取り込みバッチ（BAT0302）で前もってファイルの文字を取り出し、辞書で**単語に区切って DB に登録**しておく。同じ単語は 1 つにまとめ（TBL0201）、ファイルとは ID で結ぶ（TBL0202）ので、文章そのものは保存しない。検索のキーワードも同じ辞書で区切り、すべての単語を含むファイルを返す。

辞書は IPADIC（一般的な日本語の辞書）を使う。業界用語・社内の用語などは利用者が辞書に登録できる（TBL0204）。

## 2. 対象データ

| データ | 持ち主 | 説明 |
|---|---|---|
| 単語（TBL0201） | システム | ファイルから取り出した単語。同じ単語は 1 行 |
| ファイルと単語の対応（TBL0202） | システム | どのファイルにどの単語があるか |
| 取り込みの状態（TBL0203） | システム | ファイルごとの取り込んだときの更新日時・サイズ・辞書の版・結果 |
| 検索の辞書（TBL0204） | 全員 | 利用者が登録した単語 |

## 3. 権限

| 操作 | 利用者 | 管理者 |
|---|---|---|
| 中身での検索 | ○ | ○ |
| 辞書・取り込み状況の参照 | ○ | ○ |
| 辞書の登録・削除 | ○（ローカルモード）/ ×（共有モード） | ○ |

| FN0202-BR04 | 100 MB を超えるファイルは取り込まない（「大きすぎて対象外」）。取り出した文字は 500 万文字までを使う | 取り込みに時間がかかり、DB が膨らむため |
| FN0202-BR05 | 単語の区切り: 文字を正規化（NFKC。全角英数字・半角カナをそろえ、英字は小文字）してから、辞書で単語に区切る。普通の区切り（「関西国際空港」）と細かい区切り（「関西」「国際」「空港」）の両方を登録する。助詞・助動詞・記号・フィラー、ひらがな 1 文字、50 文字を超える語は登録しない | 複合語の一部でも見つかるようにするため。検索に使わない語で容量を使わないため |
| FN0202-BR06 | 検索: キーワードを同じく正規化して普通の区切りで単語にし、すべての単語を含むファイルを返す（AND）。それぞれの単語は、登録した単語との部分一致で探す（`LIKE '%単語%'`。例: 検索語「消費税」は「消費」「税」と区切られ、文章の「消費税込み」の「消費」「税込み」に一致する）。結果は、検索語の単語と完全に一致した単語の多いファイルを先に並べる（FN0202-BR07）。空白で区切った語もすべて含むものとする。単語に区切った結果が空（助詞だけなど）なら中身では探さない | - |
| FN0202-BR07 | 検索結果は、名前で見つかったノードのあとに、中身で見つかったファイルを、完全に一致した単語の多い順（同じならパスの順）に最大 200 件並べ、「中身に一致」と表示する。名前でも見つかったものは名前の方だけに出す。ファイルが消えていれば出さない。一致した箇所の前後の文章（抜粋）は出さない | 容量を抑えるため、文章そのものは保存しない（ユーザーの判断） |
| FN0202-BR08 | 消えたファイル・フォルダになったもの・対象外の形式になったものは、次の取り込みで単語と状態を消す。ノードの行を消したとき（削除・ゴミ箱・ノード同期・移動先の古い行）は、その場で単語と状態も消す。取り込みのたびに、ノードの行が無い単語と状態も消す（以前の版で残ったもののため）。どのファイルからも使われなくなった単語も消す | 容量を抑えるため |
| FN0202-BR09 | 辞書に登録する単語は、正規化（FN0202-BR05 と同じ）したうえで 1〜50 文字。空白・カンマ・ダブルクォートを含むもの、記号だけのものは登録できない。同じ単語は登録できない（409） | ファイルの中身と同じ形で照らし合わせるため |
| FN0202-BR10 | 辞書は全員の検索に効くため、共有モードでは管理者だけが登録・削除できる（それ以外は 403）。参照は全員ができる | - |
| FN0202-BR11 | 辞書を変えると、辞書の版（単語の一覧から計算）が変わり、すべてのファイルを順に取り込み直す。取り込み直すまでは前の辞書で区切った単語で検索する | 辞書の単語で区切り直すため |
| FN0202-BR12 | 1 回の取り込みは 45 秒まで。残りは次の回に回す。前の回が終わっていなければ、その回は何もしない | バッチが重ならないようにするため |
| FN0202-BR13 | 読めなかったファイル（壊れている・パスワード付きなど）は「読めなかった」として記録し、更新されるまで取り込み直さない | 毎回失敗を繰り返さないため |
| FN0202-BR14 | 画像の中の文字を、アプリに組み込んだ文字認識（PaddleOCR の PP-OCRv6 small を ONNX Runtime で動かす）で読んで取り込む。対象は次の 4 つ。(1) PDF の文字の無いページ（取り出した文字が空白を除いて 10 文字未満。スキャンした書類・白黒の複合機の形式（CCITT・JBIG2）・JPEG 2000・文字を図形にしたもの）。(2) PDF の、200×60 画素以上の画像（画面の写しなど。Form の中の画像も）のあるページ。(1)(2) はページを 200 dpi 相当（長い辺 2200〜4000 画素）の画像に描いて読む（画像の入り方にかかわらず、見えるとおりに読むため）。ページ数の上限は無い。(3) Excel（`xlsx` `xlsm` `xlsb`）・Word（`docx` `docm`）・PowerPoint（`pptx` `pptm`）に貼り付けた画像（`png` `jpg` `bmp` `gif` `tif` `webp`。EMF・WMF は対象外）。(4) 画像ファイル（`png` `jpg` `jpeg` `bmp` `gif` `tif` `tiff` `webp`）。48×16 画素より小さい画像と、4,000 万画素を超える画像は読まない。長い辺が 4000 画素を超える画像は縮めて読む。自信が 0.5 未満の読み取りは登録しない。形の似たカタカナと漢字（カと力・ロと口・エと工・ニと二・ハと八・トと卜・タと夕）は、前後がカタカナのとき、または次が「ー」のときカタカナに直す（例:「オ力ピ」→「オカピ」） | PDF・Excel の中身の検索はアプリの目玉のため、画像の中の文字も探せるようにする。外部のソフトを入れずにアプリだけで完結させるため。日本語の精度が高いため（試験で、スキャンした A4 の契約書をほぼすべて正しく読めた） |
| FN0202-BR15 | 文字認識のモデル（`pp-ocrv6_small_det.onnx`・`pp-ocrv6_small_rec.onnx`・`ppocrv6_dict.txt`。約 31 MB）は `models` フォルダに置く。デスクトップアプリはインストーラー・AppImage に同梱し、共有サーバーは `config.toml` の `ocr_models_dir`（既定は設定ファイルの横の `models`。OP0003・OP0007）で指定する。モデルはビルドのときに PaddlePaddle の公式の配布元から取得し、SHA-256 で確かめる（OP0002）。起動したときに 1 回だけモデルがあるかを調べ、無ければ文字認識だけを飛ばす（画像ファイルは対象外になり、PDF・Office は文字だけを取り込む）。使えるかは設定画面の「対応するファイル」に出す。モデルを置いて起動し直すと、PDF・画像・Office だけを取り込み直す。1 回の取り込みの中では、文字認識の要るファイルをほかのファイルの後に回し、それぞれ小さい順に取り込む。1 つのファイルは途中で止めない（FN0202-BR12 の 45 秒を超えても、そのファイルは最後まで読む。200 ページで数分）。読んでいる間は、ファイルと進み具合（何ページ目・何枚目）を「ファイルの取り込み状況」に出す。使うコアは論理コアの 3 分の 1（1〜4）。メモリは最大約 600 MB 使い、取り込みの回が終わったら手放す | 文字認識は 1 ページ約 1 秒（リリースビルド）かかるため、ほかのファイルを待たせないため。作業中の PC・ほかの利用者を重くしないため |

## 5. 処理の流れ

### 5.1 取り込み

1. ノード同期（BAT0301）で `node` テーブルにファイルを登録する。
2. 取り込み（BAT0302）で、変わったファイルの文字を取り出し、単語に区切って登録する。

### 5.2 検索

1. ホームで検索すると（FN0201）、API0201 が名前の検索のあとに中身の検索を行い、結果に加える。
2. 結果をクリックすると、名前で見つかったときと同じくフォルダ画面でその場所を開く。

### 5.3 辞書の登録

1. 設定画面の「検索の辞書」で単語を入力して「登録」を押すと API0203 を呼び、サーバーの文言を表示する。
2. ゴミ箱のボタンで MSG0213 の確認を出し、OK なら API0204 を呼ぶ。
3. 同じ画面の「ファイルの取り込み状況」（API0205）で、取り込み済み・取り込み直し待ちの数を確かめられる。

## 9. 未決事項

- 古い形式の Word・PowerPoint（`.doc` `.ppt`）、一太郎（`.jtd`）、Visio などへの対応（現行は対象外）
- 部分一致（FN0202-BR06）で、1 文字の単語（「税」「会」など）を含む検索語は、関係の薄いファイルも見つかりやすい（完全に一致したファイルは先に並ぶ。FN0202-BR07）
- 区切った単語の組み合わせで一致するため、離れた場所に単語があっても一致する（例: 「定例会議」は「定例」「会議」を両方含むファイルに一致する）
- 共有モードで管理者以外も辞書を登録できるようにするか
- 文字認識の精度の確認（手書き・縦書き・とても小さい文字・傾いたスキャン）。より大きなモデル（PP-OCRv6 medium。約 130 MB）にするか
- スキャンした PDF に限って、100 MB の上限（FN0202-BR04）を上げるか（カラーで細かくスキャンした 200 ページの PDF は超えることがある）
- 文字認識をしている間の取り込みの中断（共有サーバーを止めるとき、読みかけのファイルは次の起動で最初から読み直す）
