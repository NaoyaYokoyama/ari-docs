# FN0102 ユーザー管理

## 1. 概要

共有モードで、ari-docs を使うユーザーを登録・削除し、パスワードを再設定する。行えるのは管理者だけで、最初の管理者はサーバーにユーザーが 1 人もいないときにログイン画面から登録する。ローカルモードでは使わない。

## 2. 対象データ

| データ | 持ち主 | 説明 |
|---|---|---|
| ユーザー（TBL0101） | システム | ユーザー ID・表示名・パスワードのハッシュ・権限（`role_id`: `admin` / `user`） |

## 3. 権限

| 操作 | 利用者 | 管理者 |
|---|---|---|
| ユーザーの一覧・登録・削除・パスワードの再設定 | × | ○ |
| 自分のパスワードの変更（API0704） | ○ | ○ |

## 4. 業務ルール

| ID | ルール | 理由 |
|---|---|---|
| FN0102-BR01 | 管理者は `user.role_id` が `admin` のユーザー。ユーザー管理の API は、共有モードの管理者だけが使える（それ以外は 403） | 社内向けのため、知らない人がアカウントを作れないようにするため |
| FN0102-BR02 | サーバーにユーザー（`local` を除く）が 1 人もいないときだけ、ログイン画面で最初の管理者を登録できる。登録したらそのままログインする。同時に 2 人が登録しようとしても 1 人しか登録されない | サーバーを用意した人がそのまま管理者になれるようにするため |
| FN0102-BR03 | ユーザー ID は 1〜32 文字の半角英数字と `_` `.` `-`。`local` は使えない。同じユーザー ID は登録できない（409） | ログイン時に打ちやすく、ローカルモードのユーザーと混ざらないようにするため |
| FN0102-BR04 | 表示名は前後の空白を除いて 1〜30 文字 | - |
| FN0102-BR05 | パスワードは 8〜128 文字。Argon2 のハッシュで保存し、ログには出さない | - |
| FN0102-BR06 | ユーザーを削除すると、そのユーザーの Note・お気に入り・ユーザー設定と、その Note を指すお気に入りも削除する。そのユーザーが作った Wiki は残す | Note は本人だけのもの、Wiki は全員で共有するもののため（FN0401・FN0501） |
| FN0102-BR07 | 自分は削除できない | 管理者が 1 人もいなくなるのを防ぐため |
| FN0102-BR08 | 削除・パスワードの再設定をしたユーザーは、ログアウトさせる（セッションを消す） | 古いパスワードのまま使い続けられないようにするため |
| FN0102-BR09 | ユーザー管理は設定画面（SCR0701）の「ユーザー管理」で行う。共有モードの管理者にだけ表示する | - |

## 5. 処理の流れ

### 5.1 最初の管理者の登録

1. ログイン画面を開くと API0104 を呼び、`needsAdmin` が true なら管理者の登録フォームを表示する。
2. ユーザー ID・表示名・パスワード（確認用も）を入力して登録すると API0105 を呼び、そのままホームを表示する。

### 5.2 ユーザーの登録・削除・パスワードの再設定

1. 設定画面の「ユーザー管理」を開くと API0106 で一覧を表示する。
2. 「ユーザーを登録」でダイアログを開き、ユーザー ID・表示名・初期パスワード・管理者にするかを入力して API0107 を呼ぶ。MSG0103 を表示して一覧を再読み込みする。
3. 鍵のボタンでパスワードの再設定ダイアログを開き、API0109 を呼ぶ。MSG0105 を表示する。
4. ゴミ箱のボタンで MSG0106 の確認を出し、OK なら API0108 を呼ぶ。MSG0104 を表示して一覧を再読み込みする。
5. 失敗したら、サーバーの文言をダイアログ（削除はメッセージ）に表示する。

## 6. メッセージ

| ID | 表示する場面 | 文言 |
|---|---|---|
| MSG0103 | 登録成功 | ユーザーを登録しました |
| MSG0104 | 削除成功 | ユーザーを削除しました |
| MSG0105 | パスワードの再設定成功 | パスワードを再設定しました |
| MSG0106 | 削除の確認 | ユーザー「{表示名}（{ユーザーID}）」を削除しますか？そのユーザーの Note とお気に入りも削除します（Wiki は残ります） |

## 8. 決定事項

| 日付 | 内容 | 理由 |
|---|---|---|
| 2026-10-30 | ユーザーは管理者が登録する。最初にログイン画面から登録した人を管理者にする（FN0102-BR02） | ユーザーの判断 |
| 2026-10-30 | 権限は `user.role_id`（`admin` / `user`）で持ち、`role` テーブル（TBL0102）は使わない | 管理者かどうかの 2 種類で足りるため |
| 2026-10-30 | ユーザー ID・表示名・パスワードの制約（FN0102-BR03〜BR05） | 実装時に決めた（ユーザーの確認待ち） |

## 9. 未決事項

- 管理者・利用者の切り替え（現行は登録時にだけ決められる）
- 表示名の変更を管理者が行えるようにするか（現行は本人だけが設定画面で変えられる）
- 最初の管理者の登録を、サーバーに最初に接続した人が誰でもできてよいか（サーバーを起動したらすぐ登録する運用とする。OP0007）
