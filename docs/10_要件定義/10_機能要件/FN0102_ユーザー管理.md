# FN0102 ユーザー管理

## 1. 概要

共有モードで、ari-docs を使うユーザーを登録・削除し、パスワードを再設定する。行えるのは管理者だけで、最初の管理者はサーバーにユーザーが 1 人もいないときにログイン画面から登録する（ほかの PC からは登録用のコードが要る）。管理者の操作は、登録した PC（管理者の PC）からだけできる。管理者は利用者に、検索の辞書・全員の検索の対象外・バックアップの許可を付けられる。ローカルモードでは使わない。

## 2. 対象データ

| データ | 持ち主 | 説明 |
|---|---|---|
| ユーザー（TBL0101） | システム | ユーザー ID・表示名・パスワードのハッシュ・権限（`role_id`: `admin` / `user`） |
| 利用者の許可（TBL0105） | システム | 管理者が利用者に付けた許可（`dictionary`・`exclusion`・`backup`） |
| 管理者の PC（TBL0106） | システム | 管理者の操作をしてよい PC の鍵の SHA-256 |

## 3. 権限

| 操作 | 利用者 | 管理者 |
|---|---|---|
| ユーザーの一覧・登録・削除・パスワードの再設定・許可の変更 | × | ○（登録した PC から） |
| 管理者の PC の一覧・コードの発行・削除 | × | ○（登録した PC から） |
| この PC を管理者の PC にする（コードを入れる） | × | ○ |
| 検索の辞書・全員の検索の対象外・バックアップ（取る・設定） | 許可を付けられたら ○ | ○（登録した PC から） |
| 自分のパスワードの変更（API0704） | ○ | ○ |

## 4. 業務ルール

| ID | ルール | 理由 |
|---|---|---|
| FN0102-BR01 | 管理者は `user.role_id` が `admin` のユーザー。ユーザー管理の API は、共有モードの管理者だけが使える（それ以外は 403） | 社内向けのため、知らない人がアカウントを作れないようにするため |
| FN0102-BR02 | サーバーにユーザー（`local` を除く）が 1 人もいないときだけ、ログイン画面で最初の管理者を登録できる。登録したらそのままログインし、登録した PC を管理者の PC にする（FN0102-BR12）。同時に 2 人が登録しようとしても 1 人しか登録されない。ほかの PC から登録するときは登録用のコードが要る。コードはユーザーがいない（または管理者の PC が 1 台も無い）共有サーバーが起動したときに作り、起動した画面（標準出力）とデータのフォルダの `setup-code.txt` に書く（0・O・1・I を除いた 8 文字。大文字・小文字と `-` は問わない）。管理者の PC を登録したら（どの方法でも）消す。サーバーの PC の中（127.0.0.1）からはコード不要（リバースプロキシの後ろに置くと、すべての接続がサーバーの PC の中からに見えるので置かない。OP0007） | サーバーを用意した人がそのまま管理者になれるようにするため |
| FN0102-BR03 | ユーザー ID は 1〜32 文字の半角英数字と `_` `.` `-`。`local` は使えない。同じユーザー ID は登録できない（409） | ログイン時に打ちやすく、ローカルモードのユーザーと混ざらないようにするため |
| FN0102-BR04 | 表示名は前後の空白を除いて 1〜30 文字 | - |
| FN0102-BR05 | パスワードは 8〜128 文字。Argon2 のハッシュで保存し、ログには出さない | - |
| FN0102-BR06 | ユーザーを削除すると、そのユーザーの Note・お気に入り・ユーザー設定・本人だけの検索の対象外（FN0202-BR17）と、その Note を指すお気に入りも削除する。そのユーザーが作った Wiki は残す | Note は本人だけのもの、Wiki は全員で共有するもののため（FN0401・FN0501） |
| FN0102-BR07 | 自分は削除できない | 管理者が 1 人もいなくなるのを防ぐため |
| FN0102-BR08 | 削除・パスワードの再設定をしたユーザーは、ログアウトさせる（セッションを消す） | 古いパスワードのまま使い続けられないようにするため |
| FN0102-BR09 | ユーザー管理は設定画面（SCR0701）の「ユーザー管理」で行う。共有モードの管理者にだけ表示する | - |
| FN0102-BR10 | 管理者は、ほかのユーザーを管理者・利用者に切り替えられる（ユーザー管理の盾のボタン。API0110）。自分は切り替えられない（管理者がいなくならないように）。切り替えはすぐに効く（ログインし直さなくてよい） | 登録したあとに役割を変えられるようにするため |
| FN0102-BR11 | 管理者は、管理者でない利用者に許可を付けられる（ユーザー管理の一覧の「検索の辞書」「全員の対象外」「バックアップ」。API0111。TBL0105）。既定はどれも無し（今までどおり）。`dictionary` は検索の辞書の登録・削除（FN0202-BR10）、`exclusion` は全員の検索の対象外の変更（FN0202-BR17）、`backup` はバックアップを取る・一覧を見る・設定を変える（ダウンロード・復元・削除は管理者だけ。バックアップには全員の Note も入っているため。FN0901-BR01）。管理者には付けられない（付けなくてもすべてできる）。すぐに効く。ユーザーを削除すると消す。画面では、許可が無いものは出さない（バックアップの一覧の説明も「ダウンロード・復元・削除は管理者だけ」にする） | 管理者でない人にも、辞書の登録などを任せられるようにするため |
| FN0102-BR12 | 管理者の操作（ユーザーの管理・サーバーの設定・バックアップ・辞書など）は、登録した PC（管理者の PC。TBL0106）からだけできる。画面（デスクトップアプリ）は場所（共有サーバーの URL）ごとに鍵（32 バイトの乱数）を作ってこの PC に保存し（個人の設定 FN0701-BR15 には入れない。設定の初期化でも消さない。共有サーバーの URL を変えると鍵も変わるので、登録し直す）、すべての API に `X-Ari-Device` で送る。サーバーは鍵の SHA-256 だけを残す。登録していない PC から使う管理者は利用者として扱い、起動したときに 1 回その旨を知らせ、設定の「管理者の PC」にコードと PC の名前（一覧で見分けるため。既定は端末の名前）の入力欄を出す。PC を足すときは、登録した PC の「管理者の PC」でコードを発行し（その人あて・10 分・1 回だけ。API0113）、足す PC でそのコードを入れる（API0114）。ほかの管理者の PC も同じく発行する。登録した PC をすべて失ったときは、サーバーの登録用のコード（FN0102-BR02。サーバーの起動画面・`setup-code.txt`。無ければ入れたときに作る）で登録できる。サーバーの PC の中から使い、まだ 1 台も登録していない管理者は、ログインしたときにその PC を登録する（この PC の公開 FN0005 のあと）。利用者にした・削除した管理者の PC は消す。外す（API0115）と、その PC では管理者の操作ができなくなる | パスワードが漏れても、ほかの PC から管理者の操作をさせないため。共有サーバー（画面の無い Linux も）を毎回操作しなくても、管理者が自分の PC から管理できるようにするため |

## 5. 処理の流れ

### 5.1 最初の管理者の登録

1. ログイン画面を開くと API0104 を呼び、`needsAdmin` が true なら管理者の登録フォームを表示する。`setupCodeRequired` が true（ほかの PC から）なら、登録用のコードの欄も出す。
2. （コードと）ユーザー ID・表示名・パスワード（確認用も）を入力して登録すると API0105 を呼び、この PC を管理者の PC にして、そのままホームを表示する。

### 5.2 管理者の PC を足す

1. 登録した PC で設定の「管理者の PC」を開き（API0112）、登録する人を選んで「コードを発行」（API0113）。
2. 足す PC の ari-docs でその管理者としてログインすると、利用者として使える。設定の「管理者の PC」でコードを入れて「この PC を登録」（API0114）すると、管理者の操作ができるようになる。

### 5.3 ユーザーの登録・削除・パスワードの再設定

1. 設定画面の「ユーザー管理」を開くと API0106 で一覧を表示する。
2. 「ユーザーを登録」でダイアログを開き、ユーザー ID・表示名・初期パスワード・管理者にするかを入力して API0107 を呼ぶ。MSG0103 を表示して一覧を再読み込みする。
3. 鍵のボタンでパスワードの再設定ダイアログを開き、API0109 を呼ぶ。MSG0105 を表示する。
4. ゴミ箱のボタンで MSG0106 の確認を出し、OK なら API0108 を呼ぶ。MSG0104 を表示して一覧を再読み込みする。
5. 失敗したら、サーバーの文言をダイアログ（削除はメッセージ）に表示する。
