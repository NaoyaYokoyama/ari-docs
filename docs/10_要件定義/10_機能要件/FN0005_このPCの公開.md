# FN0005 この PC の公開

## 1. 概要

デスクトップアプリを入れた PC（共有 PC）を、そのまま共有サーバーにする。共有 PC の設定画面で管理者を登録して公開すると、ほかの PC の ari-docs から場所（FN0002-BR20）としてつなげる。サーバー機を用意して共有サーバーを構築する（OP0007）より手軽に、数人のチームで使い始めるためのもの。使う PC にはすべて ari-docs を入れる（ブラウザからは使わない）。

## 2. 対象データ

| データ | 持ち主 | 説明 |
|---|---|---|
| 公開の設定 | 共有 PC | exe のフォルダの `config.toml` の `shared_host`（共有サーバーとして使う）・`publish`（ほかの PC からつなげる）。デバッグビルドは `back/data/desktop.toml` |
| 共有 PC のデータ | 共有 PC | 自分の PC の作業フォルダ（FN0002）の `folder/` と DB。公開するとそのまま共有サーバーのデータになる |

## 3. 権限

| 操作 | 利用者 |
|---|---|
| 公開する | 共有 PC の利用者（ローカルモード） |
| 公開をやめる・また公開する | 共有 PC で、共有モードの管理者（設定画面に出すのは管理者だけ） |

## 4. 業務ルール

| ID | ルール | 理由 |
|---|---|---|
| FN0005-BR01 | 設定画面の「この PC の公開」（SCR0701）で行う。デスクトップアプリで、今の場所が自分の PC のときだけ出す。ローカルモードならだれでも、共有モードなら管理者だけに出す | 公開するのは共有 PC 自身のため |
| FN0005-BR02 | 公開するときは、管理者のアカウント（ユーザー ID・表示名・パスワード。FN0102 と同じ入力のルール）を登録する。公開する前に注意（Folder の中身がすべて見える、データが管理者に移る、ファイアウォール、スリープ、個人用に戻せない）を出し、確かめたことのチェックを入れないと公開できない | 管理者のいない共有サーバーを公開すると、最初につないだ人が管理者になれてしまうため（FN0102）。個人用のファイルが見えてしまう事故を防ぐため |
| FN0005-BR03 | 公開すると、ユーザー local（ローカルモードの本人）の Note・お気に入り・設定・Note と Wiki のフォルダ・画像・Wiki の作成者と最後に更新した人・変更履歴・辞書と対象外の登録者・ゴミ箱とバックアップの実行者を、登録した管理者に書き換え、ユーザー local は消す。1 つのトランザクションで行い、失敗したら何も変えない。もうユーザーがいれば公開しない（`service/host.rs`） | 今のデータを、そのまま管理者のものとして使い続けるため（ユーザーの選択） |
| FN0005-BR04 | 公開すると `config.toml` に `shared_host = true`・`publish = true` を書いてアプリを再起動し、自分の PC のバックエンドを共有モード（ログインあり）で `0.0.0.0` の決めたポート（既定 8080。FN0005-BR10）に待ち受ける。先に設定を書き、データを移せなかったら設定を元に戻す。共有 PC でもログインして使う | ほかの PC からつなげるようにするため。データを移せないまま公開しないため |
| FN0005-BR05 | 通信は HTTP（暗号化しない）。社内などプライベートのネットワークだけで使う。Windows のファイアウォールの確認では「プライベート ネットワーク」だけを許可するよう、画面で知らせる | プライベートのネットワークで使うので HTTP でよい（ユーザーの判断）。証明書の用意をしなくて済むため |
| FN0005-BR06 | 公開をやめると `publish = false` にして再起動し、共有モード（ログインあり）のまま `127.0.0.1` だけで待ち受ける（共有 PC の中からだけ使える）。ほかの人のアカウント・Wiki などは残り、また公開すれば戻る。個人用（ローカルモード）には戻せない | ほかの人のデータを残したまま、一時的に締め出せるようにするため（ユーザーの選択） |
| FN0005-BR07 | 公開している間、ほかの PC に伝える URL（`http://<PC の名前>:<ポート>` と `http://<IP アドレス>:<ポート>`）を設定画面に出し、コピーできるようにする。ほかの PC は設定の「場所」（FN0002-BR20）で共有サーバーとして追加する | PC の名前は IP アドレスが変わっても使えるため |
| FN0005-BR08 | 共有 PC を使う人は、共有サーバーと同じく「ユーザー管理」（FN0102）でほかの人を登録し、バックアップ（FN0901）・アプリの更新の配布物（FN0904）も共有サーバーと同じ扱いにする | 共有サーバーと同じ仕組みで動かすため |
| FN0005-BR09 | 共有 PC の中（自分の PC の場所）でも、ほかの PC と同じくファイルはダウンロードして開き、保存したらサーバーに戻す（FN0301-BR21・BR28）。「ファイルの場所を開く」は出さない | だれが使っても同じ動きにするため（ユーザーの判断） |
| FN0005-BR10 | 待ち受けるポートは、公開するときに決め（既定 8080。1024〜65535）、公開したあとも設定画面の「ポート」で変えられる（API0013。`config.toml` の `host_port`。変えると再起動する）。変えたら、ほかの PC の「場所」の URL も直す。起動したときにそのポートが使われていれば、ほかのポートに変えずに起動エラーにする | ほかのアプリと重なったときに直せるようにするため（ユーザーの判断）。伝えた URL が黙って変わらないようにするため |

## 5. 処理の流れ

1. 公開する: 共有 PC の設定画面で注意を読み、管理者を登録して「公開する」を押す（API0011）。設定を書き、データを管理者に移してアプリを再起動する。
2. 再起動したら、共有 PC でも管理者でログインする。設定画面に出る URL をほかの人に伝え、ユーザー管理でアカウントを登録する。
3. ほかの PC: 設定の「場所」に URL を追加し、切り替えてログインする。
4. 公開をやめる・また公開する: 共有 PC の設定画面で押す（API0012）。アプリを再起動する。
