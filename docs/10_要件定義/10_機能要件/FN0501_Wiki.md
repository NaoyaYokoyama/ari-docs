# FN0501 Wiki

## 1. 概要

共有ナレッジ用の Markdown の文書。一覧・作成・編集・削除・お気に入り登録ができる。ローカルモードでは利用者 1 人が使い、操作は Note（FN0401）とほぼ同じ。共有モードでは、ログインしたユーザー全員が参照・編集・削除できる（FN0501-BR01）。

## 2. 対象データ

| データ | 持ち主 | 説明 |
|---|---|---|
| Wiki（TBL0501） | ユーザー `local` | タイトルと Markdown の本文。`user_id` は作成者を表す |

## 3. 権限

| 操作 | 利用者 |
|---|---|
| 一覧・参照・作成・更新・削除 | ○ |

## 4. 業務ルール

| ID | ルール | 理由 |
|---|---|---|
| FN0501-BR01 | `user_id` は作成者を表すだけで、一覧・参照・更新・削除の絞り込みには使わない | 共有モードで全員が使えるようにするため（決定事項を参照） |
| FN0501-BR02 | タイトルは作成・更新とも 25 文字以内（Note と同じ）。違反時は 400（「タイトルは25文字以内で入力してください。」）。作成・更新とも、前後の空白を除いて空なら 400（「タイトルを入力してください。」） | サーバー側で入力チェックしている。空白だけのタイトルは一覧で見分けられないため |
| FN0501-BR03 | 一覧はタイトルの昇順で、すべて返す | 31 件目以降が表示されない問題があったため（旧 RQ0501） |
| FN0501-BR04 | Wiki を削除すると、その Wiki のお気に入りも削除する | 存在しない Wiki のお気に入りが残らないようにするため |
| FN0501-BR05 | 更新すると `updated_at` を現在日時にする | - |
| FN0501-BR06 | 未保存の変更があるとき、別の Wiki を選ぶ・別の画面へ移動する前に確認する | 編集内容を失わないため |
| FN0501-BR07 | `Ctrl+S` で保存する | - |
| FN0501-BR09 | 保存すると、最後に更新した人（`wiki.updated_by`）を記録し、画面の「更新」の横に表示名を出す。まだ誰も更新していなければ作成者を出す | 共有モードで誰が変えたか分かるようにするため（旧 RQ0502） |
| FN0501-BR10 | 保存のとき、開いたとき（または前に保存したとき）の更新日時と今の更新日時が違えば、「{名前}さんが {日時} に更新しています。上書きすると…」（MSG0516）で確かめる。OK なら上書きし、キャンセルなら保存せずに編集中の内容を残す | 同時に編集したとき、後から保存した人が黙って上書きしないようにするため |
| FN0501-BR08 | 画面の操作（表示の切り替え・作成ダイアログ・一覧の絞り込みと並べ替え・ショートカット・保存の入力チェック・更新日時の表示）は Note と同じ（FN0401-BR09〜BR14）。作成ダイアログのタイトルは 25 文字まで（FN0501-BR02） | Note と同じ画面の部品で作るため |
| FN0501-BR11 | 同時編集のお知らせ（共有モード）: Wiki を開いたときと開いている間 1 分ごとに、書いている人を確かめる（後から開いた人にもすぐ分かるように）。未保存の変更がある間は、書き始めたときと 2 分ごとにサーバーへ「書いている」と知らせる（API0507）。ほかに書いている人がいれば「○○ さんがこの Wiki を書いています」（自分も書いていれば「○○ さんも」）、開いたあとにほかの人が保存していれば「○○ さんが保存しました」を本文の上に出す。保存した・変更を捨てた・ほかの Wiki に移ったら「やめた」を知らせる。サーバーは書いている人をメモリにだけ覚え、10 分知らせがなければ忘れる | つなぎっぱなし（Teams のような常時の接続）にすると重くなるため、決まったときだけ聞く（ユーザーの判断）。保存のときの確認（FN0501-BR10）の前に気づけるようにするため |
| FN0501-BR12 | 書いている間のロック（共有モード。サーバーの設定の「Wiki を書いている間はロックする」。既定はオン。FN0902-BR10）: だれかが Wiki を書き始めたら（タイトル・本文を変えたら）、その人が保存する・変更を捨てる・ほかへ移る・止まって 10 分たつまで、ほかの人はその Wiki を読むだけにする（表示はプレビューにし、編集・分割は押せない）。本文の上に「🔒 ○○ さんが書いています（HH:MM から）」を出す。ほかの人の保存・削除はサーバーが 423 で断る。管理者はお知らせの「ロックを外す」で外せる。オフのときは BR11 のお知らせだけで、保存のときに上書きするかを確かめる（BR10） | 同じ Wiki を同時に書いて片方の変更が消えるのを防ぐため（ユーザーの依頼 2026-11-28） |

## 5. 処理の流れ

Note（FN0401 の 5 章）と同じ。呼ぶ API は API0501〜API0505、お気に入りは API0604。

## 8. 決定事項

| 日付 | 内容 | 理由 |
|---|---|---|
| 2026-10-11 | Wiki の `user_id` は作成者を表すだけとし、絞り込みに使わない（FN0501-BR01） | 共有モードでは全員が参照・編集・削除できるようにするため（ユーザーの判断） |
| 2026-10-30 | 作成・更新で空白だけのタイトルを 400 にし、更新のタイトルを 25 文字以内にする（FN0501-BR02） | ユーザーの依頼（残課題のうちおすすめのものを実装）。Note（FN0401-BR03）と揃えるため。作成 20 文字・更新 25 文字の違いは未決のまま |
| 2026-10-16 | 画面を Note と共通にする（FN0501-BR08） | 見た目と使い勝手の仕上げ（ユーザーの依頼）。2 つの画面のコードがほぼ同じだったため |
| 2026-10-30 | 一覧の 30 件の制限をなくし（旧 RQ0501）、最後に更新した人を記録し（FN0501-BR09。旧 RQ0502）、保存のときにほかの人の更新を確かめる（FN0501-BR10） | ユーザーの依頼（おすすめの機能・修正案をすべて対応） |
| 2026-11-22 | Wiki の作成のタイトルも 25 文字までにする（FN0501-BR02） | おすすめで決めた。ユーザーが確認した（2026-11-23 の QA）。Note と更新に揃えた |
| 2026-11-23 | 同時編集のお知らせを入れる。未保存の変更がある間だけ 5 分ごとに聞く（FN0501-BR11・API0507） | ユーザーの判断（2026-11-23 の QA。常に接続を保たない）。5 分・11 分・文言はおすすめで決めた（2026-11-28 にユーザーが確認した） |
| 2026-11-28 | 開いたときにも書いている人を知らせる（BR11）。書いている間はロックし、管理者が設定でオン・オフできる（既定はロック。BR12）。ロックは書き始めたときから、止まって 10 分で外れる | ユーザーの依頼と判断（2026-11-28 の QA） |
