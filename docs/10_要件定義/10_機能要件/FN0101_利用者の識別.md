# FN0101 利用者の識別

## 1. 概要

動作モードによって、処理するユーザーの決め方を変える。

- ローカルモード（個人用）: 利用者は 1 人で、ログイン操作なしでユーザー `local` として処理する
- 共有モード（共有サーバー）: ユーザー ID とパスワードでログインし、ログインしたユーザーとして処理する。ユーザーの登録は管理者が行う（FN0102）

## 2. 対象データ

| データ | 持ち主 | 説明 |
|---|---|---|
| ユーザー（TBL0101） | システム | ローカルモードはユーザー ID `local` の 1 行。共有モードは登録したユーザー |
| セッション | バックエンドのメモリ | セッション ID（トークン）とユーザー ID の対応 |

## 3. 権限

| 操作 | 利用者 | 管理者 |
|---|---|---|
| アプリの全機能（ユーザー管理を除く） | ○ | ○ |
| ユーザー管理（FN0102） | × | ○（共有モードだけ） |

## 4. 業務ルール

| ID | ルール | 理由 |
|---|---|---|
| FN0101-BR01 | ローカルモードでは、すべての API をログイン操作なしでユーザー `local` として処理する | 1 人で使うため認証は不要 |
| FN0101-BR02 | ローカルモードで DB にユーザー `local` が無いとき、ユーザーのデータを扱う API は 401 を返す | 処理するユーザーを特定できないため |
| FN0101-BR03 | Note・Wiki・お気に入りには、作成・登録したユーザーを記録する | ユーザーごとにデータを分けるため（Note は本人だけ、Wiki は全員。FN0401・FN0501） |
| FN0101-BR04 | フロントは起動時に API0101 でユーザー情報（ユーザー ID・表示名・動作モード・管理者か）を取得する。取得できなければログイン画面（SCR0004）を表示する | - |
| FN0101-BR05 | ローカルモードでは、バックエンドの起動時にユーザー `local`（表示名「ローカルユーザー」）が無ければ作る | 手作業で登録しなくても使えるようにするため（FN0101-BR02 の 401 を起こさないため） |
| FN0101-BR06 | ローカルモードのバックエンドは `127.0.0.1` だけで待ち受ける（設定の `bind_address` は使わない）。共有モードは `bind_address`（既定 `0.0.0.0`）で待ち受ける | 個人用のデータをほかの PC から見られないようにするため |
| FN0101-BR07 | 共有モードでは、ログイン（API0102）したユーザーとして処理する。未ログインは 401 | ユーザーごとにデータを分けるため |
| FN0101-BR08 | セッションは、`Authorization: Bearer <トークン>` ヘッダー、無ければ Cookie（`session_id`）で識別する。デスクトップアプリはトークンを PC（`localStorage` の `ari-docs-token`）に保存し、次の起動でもログインしたままにする | デスクトップアプリの画面（`tauri://localhost` など）と共有サーバーはオリジンが違い、Cookie が送られないため。ブラウザ（開発時）は Cookie で動くようにするため |
| FN0101-BR09 | セッションは DB（TBL0103）に保存し、最後に使ってから決まった日数（FN0902。既定 30 日）で切れる（Cookie も同じ日数）。バックエンドを再起動してもログインしたまま。期限切れのものは定期の処理（BAT0901）で消す | 再起動のたびに全員がログインし直さなくてよいようにするため |
| FN0101-BR10 | ユーザー `local` には共有モードでログインできない（パスワードを持たない） | ローカルモード用のユーザーのため |
| FN0101-BR12 | 同じユーザー ID で続けて決まった回数（FN0902。既定 5 回）ログインに失敗したら、決まった時間（既定 15 分）ログインできなくする（429、MSG0107）。管理者がロックする時間を短くしたら、ロック中の人にもすぐ効く（長くしても今のロックは延ばさない）。ロック中の失敗は数えない。成功したら数え直す。無いユーザー ID も同じように数える（TBL0104） | パスワードを総当たりで試されないようにするため。ユーザー ID があるかどうかを見分けられないようにするため |
| FN0101-BR13 | パスワードを変えたら（API0704）、本人のほかのセッションを消す（ほかの PC はログアウトする） | パスワードを知られたときに締め出せるようにするため |
| FN0101-BR14 | 共有モードでは、設定（`tls_cert`・`tls_key`。PEM 形式）があれば HTTPS で待ち受ける（OP0007）。利用者の PC がその証明書を信頼していないと、デスクトップアプリから接続できない | 通信を暗号化し、パスワードとトークンを平文で流さないため |
| FN0101-BR15 | 設定画面の「パスワードとログイン」に、本人のログイン中の端末（端末の名前・最後に使った日時（1 時間に 1 回だけ更新する）・ログインした日時。今の端末には印）を出し、1 台ずつ、またはほかの端末をすべてログアウトさせられる（API0705・API0706）。端末の名前は、ログインのときに画面が OS とアプリ・ブラウザから作って送る（例: `Windows・デスクトップアプリ`）。トークンそのものは画面に返さない | PC を替えた・なくしたときに、パスワードを変えなくても締め出せるようにするため |
| FN0101-BR11 | ログイン画面は、開いたときに API0104 で接続を確かめる。接続できなければその旨と「再接続」を表示し、デスクトップアプリでは接続先（使い方。FN0002）を変えられるようにする。ユーザーが 1 人もいなければ、最初の管理者の登録（FN0102-BR02）を表示する | サーバーが止まっている・URL が違うときに、ログインに失敗した理由が分かるようにするため |

## 5. 処理の流れ

### 5.1 起動時

1. フロントが API0101 を呼ぶ。
2. 成功したら、ユーザー情報を保持してメイン画面（ホーム）を表示する。失敗したらログイン画面（SCR0004）を表示する（ローカルモードでは通常起きない）。

### 5.2 ログイン（共有モード）

1. ログイン画面で API0104 を呼び、接続とユーザーの有無を確かめる（FN0101-BR11）。
2. ユーザー ID とパスワードを入力して「ログイン」を押すと API0102 を呼ぶ。成功したらトークンを保存してホームを表示する。失敗したら MSG0101 を表示する。

### 5.3 ログアウト（共有モード）

1. ヘッダーの「ログアウト」を押すと API0103 を呼び、保存したトークンを消してログイン画面に戻る。

## 6. メッセージ

| ID | 表示する場面 | 文言 |
|---|---|---|
| MSG0101 | ログイン失敗 | ユーザーIDまたはパスワードが違います |
| MSG0107 | ログインのロック | ログインに続けて失敗したため、{FN0902 の分数} 分間ログインできません。しばらくしてからお試しください |
| MSG0108 | 端末のログアウト | {件数} 台の端末をログアウトさせました |
| MSG0109 | ほかの端末をすべてログアウトする確認 | この端末以外の {件数} 台をログアウトさせますか？その端末では、もう一度ログインが必要になります |
| MSG0102 | サーバーに接続できない | {URL} に接続できません。サーバーが動いているか、ネットワークにつながっているかを確認してください。 |

## 8. 決定事項

| 日付 | 内容 | 理由 |
|---|---|---|
| 2026-10-11 | 設計はローカルモードだけを対象とし、共有モードは今後の課題とする | ユーザーの判断。2026-10-30 に共有モードを対象に加えた（下の行） |
| 2026-10-11 | ユーザー `local` はバックエンドの起動時に自動で作る（FN0101-BR05） | 配布するアプリで手作業の登録をなくすため |
| 2026-10-30 | 共有モードを設計の対象に加える。利用者はデスクトップアプリから共有サーバーに接続し（FN0002）、ユーザーは管理者が登録する（FN0102）。ローカルモードは今のままログインなし | ユーザーの判断 |
| 2026-10-30 | ローカルモードは `127.0.0.1` だけで待ち受ける（FN0101-BR06） | ユーザーの判断（ローカルは外部から接続できないこと） |
| 2026-10-30 | セッションはトークン（`Authorization` ヘッダー）でも識別する（FN0101-BR08） | デスクトップアプリから共有サーバーへは Cookie が送られないため |
| 2026-10-30 | セッションを DB に保存し 30 日の期限を付け、ログインの失敗が続いたらロックし、パスワードの変更でほかのセッションを消し、HTTPS で待ち受けられるようにする（FN0101-BR09・BR12〜BR14）。ロックの回数・時間は実装時に決めた | ユーザーの依頼（おすすめの機能・修正案をすべて対応） |
| 2026-10-30 | セッションの日数・ロックの回数と時間を管理者が変えられるようにし（FN0902）、ログイン中の端末を見てログアウトさせられるようにする（FN0101-BR15） | ユーザーの依頼（設定を初心者から上級者まで満足できるものに。中身はおまかせ） |
