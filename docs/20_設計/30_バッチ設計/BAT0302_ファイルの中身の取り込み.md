# BAT0302 ファイルの中身の取り込み

## 1. 概要

| 項目 | 値 |
|---|---|
| 目的 | ファイルの中身を単語に区切って DB に登録し、中身で検索できるようにする（FN0202） |
| 起動方式 | 自動 |
| 実行タイミング | 毎分 30 秒（cron: `30 */1 * * * *`。ノード同期 BAT0301 の 30 秒後）。バックエンドの起動中のみ |
| 実装 | `back/src/batch/content_index.rs`、`back/src/search/`（取り出し `extract.rs`・区切り `tokenizer.rs`・取り込み `index.rs`・文字認識 `ocr.rs` `pdf_ocr.rs`） |

## 2. 処理

1. 前の回が動いていれば何もしない（FN0202-BR12）。
2. 検索の辞書（TBL0204）から単語の区切りを用意する（辞書が変わっていれば作り直す）。
3. `node` テーブルに無いノードの、取り込みの状態（TBL0203）と単語の対応（TBL0202）を消す（以前の版で、ノードを消しても残ったもの。FN0202-BR08）。続けて `node` テーブルのすべてのノードについて、ファイルの更新日時とサイズを調べる。消えた・フォルダ・対象外の形式（FN0202-BR02）で、取り込みの状態（TBL0203）があれば、単語と状態を消す（FN0202-BR08）。
4. 状態が無い、または更新日時・サイズ・版のどれかが違うファイルを取り込む（FN0202-BR01）。版は辞書の版と取り出し方の版から決め、文字認識した PDF・画像・Office は別の版にする（モデルを置いたら取り込み直す。FN0202-BR15）。100 MB を超えるものは `too_large`（FN0202-BR04）、読めないものは `error`（FN0202-BR13）として記録する。
5. 文字認識の要るファイル（PDF・画像・Office）をほかのファイルの後に回し、それぞれ小さい順に並べる（FN0202-BR15）。
6. 取り込むファイルごとに、文字を取り出し（FN0202-BR03。画像の中の文字は文字認識で読む。FN0202-BR14）、単語に区切り（FN0202-BR05）、1 つのトランザクションでそのファイルの単語を登録し直す。文字認識している間は、ファイルと進み具合をメモリに残す（API0205）。文字認識のモデルは最初に使うときに読み込み、その回が終わったら捨てる。
7. 45 秒を過ぎたら残りは次の回に回す（FN0202-BR12）。1 つのファイルは途中で止めない（200 ページの PDF は数分かかる）。
8. 何か消した・取り込んだときは、使われなくなった単語（TBL0201）を消す。
9. 結果（取り込んだ数・次の回に回した数）をメモリに残し（API0205）、取り込んだときは `content_index: processed = N, pending = M` を標準出力に出す。

単語の区切りは時間がかかるため、API の処理とは別のスレッドで動かす。DB の書き込み中に API が待てるよう、接続には 10 秒の待ち時間（`busy_timeout`）を付ける。

## 3. 入出力

| 種類 | 対象 | 内容 |
|---|---|---|
| 入力 | `folder/` | ファイルの中身・更新日時・サイズ |
| 入力 | TBL0301 `node` | 対象のファイル |
| 入力 | TBL0204 `search_dictionary` | ユーザー辞書の単語 |
| 入出力 | TBL0203 `node_content` | 取り込みの状態 |
| 出力 | TBL0201 `keyword`、TBL0202 `node_keyword` | 単語とファイルの対応 |

## 4. エラー時の動き

- 1 つのファイルを読めないときは `error` として記録し、`content index error: <パス> <内容>` を標準エラーに出して次のファイルに進む。
- DB の失敗はその回を中断し、`content_index: <内容>` を標準エラーに出す。取り込み済みのファイルは残り、次の回で続きを取り込む。
