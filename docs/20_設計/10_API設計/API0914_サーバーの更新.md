# API0914 サーバーの更新

## 1. 概要

GitHub Releases の最新の版のサーバー一式を取ってきて、署名を確かめてから入れ替え、サーバーを起動し直す（FN0904-BR16）。

## 2. エンドポイント

| 項目 | 値 |
|---|---|
| メソッド | POST |
| パス | `/api/server-update/apply` |
| 認証 | 必要 |
| 権限 | 管理者（共有モード・登録した PC。FN0102-BR12） |
| 実装 | `back/src/api/server_update.rs`、`back/src/service/server_update.rs` |

## 3. リクエスト

本文は無し。

## 4. レスポンス

### 4.1 成功時

| 名前 | 型 | 説明 |
|---|---|---|
| message | string | 「サーバーを {版} に入れ替えました。起動し直しています」 |
| data.version | string | 入れ替えた版 |

答えを返してから約 1.5 秒後に、サーバーは同じ引数で新しい版を起動し直す。画面は `/api/server-info`（API0104）の `version` が変わるまで待つ。

### 4.2 エラー時

| ステータス | 条件 |
|---|---|
| 400 | 画面から更新できない（FN0904-BR14）・新しい版が無い・GitHub につながらない・署名が合わない・新しい版がこのサーバーで動かない・今の版より新しくない・ほかの更新やバックアップの途中・入れ替えられない（メッセージに理由） |
| 401 | ログインしていない |
| 403 | ローカルモード・管理者でない |

## 5. 処理

1. GitHub Releases の最新の版（API0913）を聞き直し、サーバー一式（`.tar.gz`）を `<データのフォルダ>/tmp/server-update/` に取ってくる。
2. FN0904-BR16 の順に入れ替える（署名を確かめる → 実行ファイルのフォルダの `.update-new/` に展開 → `back --version` で版と動くかを確かめる → DB の写し → モデル・`back` の入れ替え）。途中で失敗したら、入れ替えたものを戻して 400 を返す。
3. 答えを返してから起動し直す。
