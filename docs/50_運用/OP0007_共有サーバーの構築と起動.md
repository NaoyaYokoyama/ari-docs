# OP0007 共有サーバーの構築と起動

## 1. 概要

| 項目 | 値 |
|---|---|
| 目的 | 複数人で使う共有サーバー（共有モードのバックエンド）を用意し、利用者のデスクトップアプリから接続できるようにする |
| 実行するタイミング | 共有サーバーを新しく用意するとき・起動するとき |
| 前提 | サーバー PC で Rust（cargo）が使える（ビルドする PC と動かす PC が同じ OS なら、ビルドした `back` だけを持っていってもよい）。利用者の PC から、サーバー PC の待ち受けポート（既定 8080）に接続できる |

共有サーバーは画面を持たない。利用者はデスクトップアプリの使い方を「共有サーバーに接続」にして使う（FN0002）。

サーバー機を用意しない手軽な方法として、共有 PC のデスクトップアプリを設定画面の「この PC の公開」から共有サーバーにすることもできる（FN0005。この文書の手順は要らない）。

## 2. 手順

1. GitHub Releases から共有サーバー一式（`ari-docs-server_<版>_linux-x86_64.tar.gz`。`back`・文字認識のモデル・ライセンス）を落とす。Ubuntu 24.04 で作っているため、同じくらい新しい Linux（glibc 2.39 以降。Ubuntu 24.04・Debian 13 など）で動く。自分でビルドするときは、リポジトリの `back/` で `cargo build --release`（`back/target/release/back`・`back/models/`・`back/licenses/THIRD_PARTY_NOTICES.txt` を同じように置く）。

2. サーバー PC に置き場所を作り、一式と設定ファイルを置く（例: `/opt/ari-docs/`）。動かす利用者がこのフォルダに書き込めるようにする（画面からの更新で `back`・`models` を入れ替えるため。FN0904-BR16）。

```bash
mkdir -p /opt/ari-docs/folder
tar -xzf ari-docs-server_0.1.0_linux-x86_64.tar.gz -C /opt/ari-docs
```

3. `/opt/ari-docs/config.toml` を書く。相対パスは設定ファイルのフォルダから解決する。

```toml
mode = "shared"
# 待ち受けるアドレス。0.0.0.0 はすべての NIC（特定の NIC だけなら その IP アドレス）
bind_address = "0.0.0.0"
port = 8080
folder_root = "folder"
database_path = "ari.db"
docs_default_root = "folder"
# HTTPS にするとき（PEM 形式の証明書と秘密鍵。相対パスは設定ファイルのフォルダから）
# tls_cert = "cert.pem"
# tls_key = "key.pem"
# 文字認識のモデルのフォルダ（書かなければ設定ファイルの横の models）
# ocr_models_dir = "models"
```

HTTPS にするときは、社内の認証局などで発行した証明書を使い、利用者の PC がその証明書（または認証局）を信頼している状態にする。自己署名の証明書のままでは、デスクトップアプリから接続できない。URL は `https://<サーバー名>:8080` にする。

4. 設定ファイルを引数に付けて起動する（`/opt/ari-docs/` で実行）。止めるときは `Ctrl+C`。常に動かす場合は OS のサービス（systemd など）に登録する（2.1）。

```bash
./back /opt/ari-docs/config.toml
```

5. 起動した画面（標準出力。systemd なら `journalctl -u <サービス名>`）に出る「最初の管理者の登録コード」（`XXXX-XXXX`）を控える。データのフォルダ（`database_path` のフォルダ）の `setup-code.txt` にも書いてある。管理者が自分の PC のデスクトップアプリで「共有サーバーに接続」（URL は `http://<サーバー名>:8080`）を選び、ログイン画面でコードと管理者のユーザー ID・表示名・パスワードを入れて登録する（FN0102-BR02）。サーバーの PC には画面もアプリも要らない（コードを知らない人は登録できない）。登録すると `setup-code.txt` は消える。
   - 登録した PC が管理者の PC になる。管理者の操作（ユーザーの管理・サーバーの設定・バックアップなど）は、管理者の PC からだけできる（FN0102-BR12）。ほかの PC からも管理するときは、管理者の PC の設定の「管理者の PC」でコードを発行し、その PC の設定の「管理者の PC」で入れる。
   - 管理者の PC をすべて失ったときは、サーバーを起動し直すと（または、その PC で「管理者の PC」にコードを入れようとすると）登録用のコードが起動した画面と `setup-code.txt` に出るので、それを「管理者の PC」に入れる。
   - 前の版から上げたサーバーは、管理者の PC がまだ無いので、起動したときに登録用のコードを出す。管理者は、ログインして設定の「管理者の PC」にそのコードを入れる。
   - nginx などのリバースプロキシの後ろには置かない。サーバーからは、すべての接続がサーバーの PC の中（127.0.0.1）からに見え、登録用のコードを求めなくなるため（FN0102-BR02）。HTTPS は `tls_cert`・`tls_key` で行う。
6. 設定画面の「ユーザー管理」で利用者を登録し、ユーザー ID と初期パスワードを本人に伝える。検索の辞書・全員の検索の対象外・バックアップを任せる人には、一覧の許可のボタンで許可を付ける（FN0102-BR11）。
7. 利用者に、インストーラーの最初のページで「共有サーバーに接続する」と URL を入力してもらう（入れ済みなら設定画面の「場所」で共有サーバーを足す。FN0002-BR20）。
   - インストーラーには今は署名が無い（OP0002 の未決事項）。Windows で開くと「Windows によって PC が保護されました」と出るので、「詳細情報」を押してから「実行」を押してもらう。配るときは、社内の決まった場所（共有フォルダなど）から取ってもらい、メールの添付などで回さない。
8. 新しい版が出たら（OP0002 の 3.1）、管理者が管理者の PC で設定の「情報」の「サーバーの更新」から「サーバーを更新」を押す（FN0904-BR14〜BR18）。新しい版があれば、ログインしたときにもお知らせが出る。GitHub Releases の新しい版の通知がほしいときは、GitHub のリポジトリの「Watch → Custom → Releases」をオンにする。
   - サーバーは一式を取ってきて署名を確かめ、`back` と `models` を入れ替えて起動し直す（数十秒。その間は使っている人の操作が切れる）。前の版は `back.old`・`models.old`、前の DB の写しは `<データのフォルダ>/server-update/ari-<前の版>.db` に残る。
   - 利用者のアプリは、画面を読み込み直すかログインしたときに、サーバーと同じ版の更新を勧める（アプリは GitHub Releases から取る。FN0904-BR02）。
   - サーバーがインターネットにつながらないときは、管理者の PC で GitHub Releases から `ari-docs-server_<版>_linux-x86_64.tar.gz` と `.sig` を落とし、同じ画面の「ファイルから更新」で上げる（FN0904-BR17）。利用者の PC も GitHub につながらないときは、アプリの配布物と `.sig` を `<データのフォルダ>/app-update/`（上の例では `/opt/ari-docs/app-update/`）に置く（FN0904-BR11。ファイルの名前は変えない。変更点は `<配布物>.notes.md` か `notes.md`。FN0904-BR13）。
   - 画面から更新した後にサーバーが起動しないときは、サーバーの PC で前の版に戻す（下の例）。DB は新しい版のマイグレーションで変わっているので、写しに戻す。

```bash
sudo systemctl stop ari-docs
cd /opt/ari-docs
mv back back.failed && mv back.old back
[ -d models.old ] && mv models models.failed && mv models.old models
cp server-update/ari-0.1.0.db ari.db   # 前の版の DB の写し（版は戻す前の版）
rm -f ari.db-wal ari.db-shm
sudo systemctl start ari-docs
```

### 2.1 サービスへの登録（常に動かすとき）

Linux（systemd）: `/etc/systemd/system/ari-docs.service` を作り、`sudo systemctl enable --now ari-docs` で登録して起動する。止める・起動し直すは `sudo systemctl stop|restart ari-docs`、ログは `journalctl -u ari-docs`。

```ini
[Unit]
Description=ari-docs 共有サーバー
After=network-online.target
Wants=network-online.target

[Service]
# 動かす利用者（/opt/ari-docs/ に書き込めること）
User=ari-docs
WorkingDirectory=/opt/ari-docs
ExecStart=/opt/ari-docs/back /opt/ari-docs/config.toml
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Windows: タスク スケジューラで「コンピューターの起動時」に `back.exe C:\ari-docs\config.toml` を「ユーザーがログオンしているかどうかにかかわらず実行する」で登録する（開始フォルダは `C:\ari-docs`）。ファイアウォールでは「プライベート」（社内）のネットワークだけで待ち受けのポート（既定 8080）を許可する。

DB のバックアップは、管理者が設定の「バックアップ」で自動にする（FN0901。DB と `folder/` を 1 つの ZIP にする）。保存先は、サーバーの壊れに備えて別のディスクか共有フォルダにする。

## 3. 確認方法

- 起動時に `Server running: http://0.0.0.0:8080`（HTTPS なら `https://`）が表示される
- 更新ファイルを置いたら、`curl -i http://<サーバー名>:8080/api/app-update/windows/x86_64/0.0.0` で、置いた版と URL が返る（無ければ 204。API0911）
- 利用者の PC から `curl http://<サーバー名>:8080/api/server-info` を実行すると `{"app":"ari-docs","mode":"shared","needsAdmin":false}` が返る（管理者の登録前は `needsAdmin` が true）

## 4. うまくいかないとき

| 症状 | 原因 | 対処 |
|---|---|---|
| アプリで「サーバーに接続できません」 | サーバーが止まっている、ファイアウォールでポートが閉じている、URL の誤り | 3 章の `curl` で確かめる。サーバー PC のファイアウォールで待ち受けポートを開ける |
| 「このサーバーは共有モードで動いていません」 | `config.toml` の `mode` が `local` | `mode = "shared"` にして起動し直す（ローカルモードは `127.0.0.1` でしか待ち受けないため、ほかの PC からはそもそも接続できない） |
| `bind_address が正しくありません` で止まる | IP アドレスの形でない | `0.0.0.0` かサーバーの IP アドレスにする |
| `ポート 8080 を使えません` で止まる | ほかのアプリが使っている | `port` を変え、利用者の URL も合わせる |
| 「証明書・秘密鍵を読めません」で止まる | `tls_cert`・`tls_key` のパス・形式の誤り | PEM 形式のファイルを指定する |
| HTTPS にしたらアプリから接続できない | 利用者の PC が証明書を信頼していない | 証明書（認証局）を利用者の PC に入れる |
| 「15 分間ログインできません」 | 続けて 5 回失敗した（FN0101-BR12） | 15 分待つ。急ぐときは DB の `login_failure` のその行を消す |
| 「サーバーの更新」に「GitHub で新しい版を調べられませんでした」 | サーバーがインターネット（github.com）につながらない | 「ファイルから更新」を使う（2 章の 8） |
| 「新しい版がこのサーバーで動きません」 | Linux が古い（glibc 2.39 より前） | Linux を新しくするか、そのサーバーでビルドした `back` に入れ替える |
| 「… を入れ替えられません」 | 動かす利用者が `/opt/ari-docs` に書き込めない | フォルダの持ち主を動かす利用者にする |
| 更新ファイルを置いたのに、アプリで新しい版が出ない | 名前を変えた、`.sig` が無い、置いた版が利用者の版より新しくない、置き場所が `database_path` のフォルダの `app-update/` でない | 3 章の `curl` で確かめる |
| 管理者がパスワードを忘れた | - | ほかの管理者が再設定する。管理者が 1 人だけなら、DB の `user` テーブルの `role_id` を書き換えて別のユーザーを管理者にする |
