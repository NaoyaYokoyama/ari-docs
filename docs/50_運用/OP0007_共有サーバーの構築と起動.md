# OP0007 共有サーバーの構築と起動

## 1. 概要

| 項目 | 値 |
|---|---|
| 目的 | 複数人で使う共有サーバー（共有モードのバックエンド）を用意し、利用者のデスクトップアプリから接続できるようにする |
| 実行するタイミング | 共有サーバーを新しく用意するとき・起動するとき |
| 前提 | サーバー PC で Rust（cargo）が使える（ビルドする PC と動かす PC が同じ OS なら、ビルドした `back` だけを持っていってもよい）。利用者の PC から、サーバー PC の待ち受けポート（既定 8080）に接続できる |

共有サーバーは画面を持たない。利用者はデスクトップアプリの使い方を「共有サーバーに接続」にして使う（FN0002）。

## 2. 手順

1. サーバー用のバックエンドをビルドする（リポジトリの `back/` で実行）。`back/target/release/back` ができる。

```bash
cargo build --release
```

2. サーバー PC に置き場所を作り、`back` と設定ファイルを置く（例: `/opt/ari-docs/`）。

```bash
mkdir -p /opt/ari-docs/folder
cp target/release/back /opt/ari-docs/
# 文字認識のモデル（ビルドのときに back/models/ に用意される。FN0202-BR15）とライセンス
cp -r models /opt/ari-docs/
cp licenses/THIRD_PARTY_NOTICES.txt /opt/ari-docs/
```

3. `/opt/ari-docs/config.toml` を書く。相対パスは設定ファイルのフォルダから解決する。

```toml
mode = "shared"
# 待ち受けるアドレス。0.0.0.0 はすべての NIC（特定の NIC だけなら その IP アドレス）
bind_address = "0.0.0.0"
port = 8080
folder_root = "folder"
database_path = "ari.db"
docs_default_root = "folder"
# HTTPS にするとき（PEM 形式の証明書と秘密鍵。相対パスは設定ファイルのフォルダから）
# tls_cert = "cert.pem"
# tls_key = "key.pem"
# 文字認識のモデルのフォルダ（書かなければ設定ファイルの横の models）
# ocr_models_dir = "models"
```

HTTPS にするときは、社内の認証局などで発行した証明書を使い、利用者の PC がその証明書（または認証局）を信頼している状態にする。自己署名の証明書のままでは、デスクトップアプリから接続できない。URL は `https://<サーバー名>:8080` にする。

4. 設定ファイルを引数に付けて起動する（`/opt/ari-docs/` で実行）。止めるときは `Ctrl+C`。常に動かす場合は OS のサービス（systemd など）に登録する。

```bash
./back /opt/ari-docs/config.toml
```

5. **起動したらすぐに**、自分のデスクトップアプリで「共有サーバーに接続」（URL は `http://<サーバー名>:8080`）を選び、ログイン画面で最初の管理者を登録する（FN0102-BR02）。ユーザーが 1 人もいない間は、接続できる人なら誰でも管理者を登録できるため。
6. 設定画面の「ユーザー管理」で利用者を登録し、ユーザー ID と初期パスワードを本人に伝える。
7. 利用者に、インストーラーの最初のページで「共有サーバーに接続する」と URL を入力してもらう（入れ済みなら設定画面の「使い方」で変える）。

## 3. 確認方法

- 起動時に `Server running: http://0.0.0.0:8080`（HTTPS なら `https://`）が表示される
- 利用者の PC から `curl http://<サーバー名>:8080/api/server-info` を実行すると `{"app":"ari-docs","mode":"shared","needsAdmin":false}` が返る（管理者の登録前は `needsAdmin` が true）

## 4. うまくいかないとき

| 症状 | 原因 | 対処 |
|---|---|---|
| アプリで「サーバーに接続できません」 | サーバーが止まっている、ファイアウォールでポートが閉じている、URL の誤り | 3 章の `curl` で確かめる。サーバー PC のファイアウォールで待ち受けポートを開ける |
| 「このサーバーは共有モードで動いていません」 | `config.toml` の `mode` が `local` | `mode = "shared"` にして起動し直す（ローカルモードは `127.0.0.1` でしか待ち受けないため、ほかの PC からはそもそも接続できない） |
| `bind_address が正しくありません` で止まる | IP アドレスの形でない | `0.0.0.0` かサーバーの IP アドレスにする |
| `ポート 8080 を使えません` で止まる | ほかのアプリが使っている | `port` を変え、利用者の URL も合わせる |
| 「証明書・秘密鍵を読めません」で止まる | `tls_cert`・`tls_key` のパス・形式の誤り | PEM 形式のファイルを指定する |
| HTTPS にしたらアプリから接続できない | 利用者の PC が証明書を信頼していない | 証明書（認証局）を利用者の PC に入れる |
| 「15 分間ログインできません」 | 続けて 5 回失敗した（FN0101-BR12） | 15 分待つ。急ぐときは DB の `login_failure` のその行を消す |
| 管理者がパスワードを忘れた | - | ほかの管理者が再設定する。管理者が 1 人だけなら、DB の `user` テーブルの `role_id` を書き換えて別のユーザーを管理者にする |
