# OP0002 ビルド

## 1. 概要

| 項目 | 値 |
|---|---|
| 目的 | 配布物（Windows は NSIS のインストーラー、Linux は AppImage）を作る |
| 実行するタイミング | リリースするとき |
| 前提 | 開発環境を構築済み（TL0001）。tauri-cli |

## 2. 構成

| 配布物 | 内容 |
|---|---|
| アプリ本体（exe） | `desktop/src-tauri/target/release/` の実行ファイル（Windows は `.exe`）。画面（`front/dist`）を埋め込み、バックエンド（`back/` のライブラリ `ari_back`）とマイグレーションの SQL を含む。起動するとバックエンドも同じプロセスで動く |
| 配布物 | Windows: NSIS のインストーラー（ユーザー単位で `%LOCALAPPDATA%\ari-docs\` に入れる）。Linux: AppImage。`tauri.conf.json` の `bundle.targets` で指定する |

exe は書き込めるフォルダに置いて起動する。初回起動で exe と同じフォルダに `config.toml`・`folder/`・`.ari-docs/ari.db` ができる（FN0002）。

| 配布の形 | 使えるか |
|---|---|
| NSIS（Windows。ユーザー単位で `%LOCALAPPDATA%\ari-docs\` に入れる） | ○（配布物。インストール先が exe のフォルダ＝作業フォルダになる） |
| AppImage（Linux） | ○（配布物。`.AppImage` のあるフォルダが exe のフォルダになる） |
| exe（Windows・Linux）をそのまま置く | ○（配布物にはしないが使える） |
| MSI（Windows。Program Files に入れる）、deb・rpm（Linux。`/usr/bin` に入れる） | ✕（書き込めず MSG0005 になる。FN0002-BR06）。作らない |

更新とアンインストール:

| 操作 | `config.toml`・`folder/`・`.ari-docs/` |
|---|---|
| NSIS: 新しいインストーラーで上書きインストール | 残る（入れ替わるのは exe などアプリのファイルだけ） |
| NSIS: アンインストール | 残る（アンインストーラーは自分で入れたファイルだけを消し、フォルダは空のときだけ消す）。「アプリのデータを削除」も `%APPDATA%\com.aridocs.app` などで、作業フォルダは消さない |
| AppImage: 新しい `.AppImage` に置き換える | 残る（`.AppImage` だけを置き換える。フォルダごと置き換えると消える） |

## 3. 手順

1. 画面をビルドする（`front/` で実行）。

```bash
npm ci
npm run build
```

2. 配布物を作る（`desktop/src-tauri/` で実行）。その OS の配布物ができる（NSIS は Windows で、AppImage は Linux で作る。Linux で Windows の版を作る方法は下に書く）。

```bash
# Windows
cargo tauri build

# Linux（NO_STRIP は 5 章を参照）
NO_STRIP=true cargo tauri build
```

3. 配布物は `desktop/src-tauri/target/release/bundle/` 以下にできる。文字認識のモデル（`back/models/` → `models/`）とライセンス（`back/licenses/THIRD_PARTY_NOTICES.txt`）を同梱する（`tauri.conf.json` の `bundle.resources`。FN0202-BR15）（Windows は `nsis/ari-docs_<版>_x64-setup.exe`、Linux は `appimage/ari-docs_<版>_amd64.AppImage`）。

GitHub Actions でも作れる（`.github/workflows/build.yml`。Actions の画面の「Run workflow」か、`v` で始まるタグの push で動く）。Windows（NSIS）と Linux（AppImage）を作り、バックエンドとデスクトップアプリのテストも動かして、配布物を成果物（Artifacts）に置く。

Linux の PC でも Windows のインストーラーを作れる（クロスコンパイル。Tauri では試験的な扱い）。できるのは `target/x86_64-pc-windows-msvc/release/bundle/nsis/` 以下。署名はされない。

```bash
# 一度だけ（Fedora の例。Windows の SDK は cargo-xwin が初回に取得して ~/.cache/cargo-xwin に置く）
sudo dnf install clang lld llvm mingw32-nsis
rustup target add x86_64-pc-windows-msvc
cargo install cargo-xwin --locked

# desktop/src-tauri/ で
cargo tauri build --runner cargo-xwin --target x86_64-pc-windows-msvc --bundles nsis
```

バックエンドだけを開発用にビルドする場合は、リポジトリのルートで `./build.sh` を実行する（`front/dist` と `back/target/release/back`）。

## 4. 確認方法

- Windows: インストーラーの最初のページで使い方を選べる（`desktop/src-tauri/installer-hooks.nsh`。FN0002-BR11）。「共有サーバーに接続する」で、動いていない URL を入れると、接続できない旨と「このまま進めますか？」が出る（FN0002-BR18）。「個人用」で入れて起動すると、ホームが表示され、`%LOCALAPPDATA%\ari-docs\` に `config.toml`・`folder/`・`.ari-docs/` ができる（IT0002）
- Linux: 空のフォルダに `.AppImage` を置いて起動すると、使い方を選ぶ画面（SCR0003）が出る。「個人用」を選ぶと再起動してホームが表示され、その隣に `config.toml`・`folder/`・`.ari-docs/` ができる（IT0002）

## 5. うまくいかないとき

| 症状 | 原因 | 対処 |
|---|---|---|
| 初回のビルドで `文字認識のモデル（…）を取得できませんでした` の警告が出る | 文字認識のモデル（約 31 MB）をビルドのときに PaddlePaddle の配布元（`paddle-model-ecology.bj.bcebos.com`）から取得している（`back/build_models.rs`。FN0202-BR15）。つながらない・SHA-256 が合わない | インターネットにつながる環境でビルドし直す（一度取得すると `back/models/` に残る）。取得できないままでもビルドはでき、文字認識だけが使えない。取得しないときは環境変数 `ARI_DOCS_SKIP_MODELS=1` |
| 初回のビルドで `ort-sys` が止まる・失敗する | 文字認識を動かす ONNX Runtime を、ビルドのときに `cdn.pyke.io` から取得して組み込んでいる | インターネットにつながる環境でビルドする（一度取得すると `~/.cache/ort.pyke.io`・Windows は `%LOCALAPPDATA%\ort.pyke.io` に残る）。Rust は 1.95 以上が要る |
| 初回のビルドで `lindera-ipadic` が止まる・失敗する | ファイルの中身の検索（FN0202）の辞書（IPADIC）を、ビルドのときに `https://Lindera.dev/` からダウンロードしている | インターネットにつながる環境でビルドする（一度ダウンロードすると `target/` に残る）。辞書を組み込むため、exe は数十 MB 大きくなる |
| Linux で Windows の版を作ると `lld-link: error: could not open 'DirectML.lib'`（`PathCch.lib` も） | ONNX Runtime が大文字まじりの名前でライブラリを探すが、cargo-xwin が取得した SDK は小文字の名前で、Linux は大文字と小文字を区別する | `cd ~/.cache/cargo-xwin/xwin/sdk/lib/um/x86_64 && ln -s directml.lib DirectML.lib && ln -s pathcch.lib PathCch.lib` |
| `npm run build` が型エラーで止まる | 型エラーがある | `cd front && npx tsc -b` でエラーを確認して直す |
| `cargo tauri` が見つからない | tauri-cli が未インストール | `cargo install tauri-cli --version "^2.0"` |
| Linux で `failed to run linuxdeploy` で止まる（`--verbose` で `Strip call failed: … unknown type [0x13] section '.relr.dyn'`） | linuxdeploy に入っている strip が古く、新しいディストリビューション（Fedora 44 など）のライブラリを読めない | `NO_STRIP=true cargo tauri build`（ライブラリを strip しないだけで、動作は変わらない） |
