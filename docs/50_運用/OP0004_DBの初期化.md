# OP0004 DB の初期化

## 1. 概要

| 項目 | 値 |
|---|---|
| 目的 | DB の場所・作られ方を確認する。開発時に DB を作り直す |
| 実行するタイミング | DB を確認するとき、作り直すとき |
| 前提 | `sqlite3` コマンド（確認する場合） |

DB はバックエンドの起動時に自動で作られる。手作業は不要。

1. DB ファイルが無ければ作る（フォルダも作る）
2. 未適用のマイグレーションを番号順に実行する（SQL は実行ファイルに埋め込み。TBL0001）
3. ユーザー `local` が無ければ作る（FN0101-BR05）

| 使い方 | DB の場所 |
|---|---|
| デスクトップアプリ | `<作業フォルダ>/.ari-docs/ari.db` |
| 開発時 | `back/data/ari.db`（`back/config.toml` の `database_path`） |

## 2. 手順

### 2.1 DB の作り直し（開発時）

開発用の DB は使い捨て（バックアップ不要）。バックエンドを止めてから（OP0001）、`back/` で実行し、バックエンドを起動し直す。

```bash
cd back
rm data/ari.db
```

## 3. 確認方法

```bash
cd back
sqlite3 data/ari.db "select migration_name from schema_migration order by 1;"
sqlite3 data/ari.db "select user_id, display_name from user;"
```

- マイグレーションが `T001`〜`T008` まで適用されている
- ユーザー `local` がある

## 4. うまくいかないとき

| 症状 | 原因 | 対処 |
|---|---|---|
| 起動時に `Failed to execute migration` で止まる | マイグレーションの SQL の誤り | エラーの出たファイルを直す。空の DB でも通るよう `DROP TABLE IF EXISTS` を使う |
| API がすべて 401 | ユーザー `local` が無い（通常は起動時に作られる） | バックエンドを再起動する |
