# OP0006 トラブル対応

## 1. 概要

| 項目 | 値 |
|---|---|
| 目的 | 開発・動作確認中によく起きる問題の原因と対処をまとめる |
| 実行するタイミング | 問題が起きたとき |
| 前提 | - |

## 2. 手順

症状から原因を探し、対処を行う。

| 症状 | 原因 | 対処 |
|---|---|---|
| バックエンドの起動時に `ポート 8080 を使えません` で止まる。デスクトップアプリでは起動エラーの画面（SCR0002）にこのエラーが出る | ポート 8080 を別のプロセスが使っている（`cargo run` のバックエンドが残っているなど） | `ss -ltnp \| grep 8080` でプロセスを確認して止める |
| デスクトップアプリで「作業フォルダで起動できませんでした」と出る | 作業フォルダを移動・削除した。共有フォルダに繋がっていない | 作業フォルダを元に戻すか、画面で選び直す（FN0002-BR07） |
| デスクトップアプリで「exe のフォルダに書き込めません」と出る | exe を Program Files・`/usr/bin` など書き込めないフォルダに置いた | exe を書き込めるフォルダ（ホームの下など）にフォルダごと移す（FN0002-BR06） |
| 画面は出るが、新しく追加した画面・API が動かない（404 など） | バックエンドが変更前のまま動いている | バックエンドを再起動する（OP0001） |
| 画面に `Failed to resolve import "xxx"` と出る | ホストでだけパッケージを入れた。開発サーバーのコンテナの `node_modules` は別の領域 | リポジトリのルートで `docker compose exec frontend npm install` → `docker compose restart frontend` |
| API がすべて 401 になる | DB にユーザー `local` が無い（通常は起動時に作られる） | バックエンドを再起動する（OP0004） |
| バックエンドの起動時に `folder_root が見つかりません` で止まる | ノードのルート（`config.toml` の `folder_root`）が無い | OP0005 |
| API の呼び出しが CORS エラーになる | フロントを `http://localhost:5173` 以外で開いている | `http://localhost:5173` で開く（OP0003） |
| 起動時に `Failed to execute migration` で止まる | マイグレーションの SQL の誤り | OP0004 の 4 |
| Markdown ビューアで「フォルダを読み込めませんでした」と出る | 指定したパスが無い、フォルダではない | 絶対パスを確認する。空欄で「表示」を押すと `docs/` に戻る |

## 3. 確認方法

- 対処のあと、OP0001 の 3 の確認方法で起動を確かめる
