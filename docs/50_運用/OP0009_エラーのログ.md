# OP0009 エラーのログ

## 1. 概要

サーバー（共有サーバー・デスクトップアプリの中のバックエンド）のエラーを、ファイルに残す（0020_非機能要件の 5 章）。エラーだけを残し、ふつうの動き（アクセスなど）は残さない。

## 2. 場所と残し方

| 項目 | 内容 |
|---|---|
| 場所 | `<データのフォルダ>/logs/error.log`（データのフォルダは DB のあるフォルダ。デスクトップアプリは `<作業フォルダ>/.ari-docs/logs/`）。設定の「情報」の「エラーのログ」に出る（管理者・ローカルモード） |
| 書き方 | 1 行 1 件。`[YYYY-MM-DD HH:MM:SS] 内容`（この PC の時刻）。想定外の停止（panic）も `panic:` で残す |
| 大きさ | 1 MB を超えたら `error.log.1` にずらし、`error.log.5` まで残す（それより古いものは消える）。合わせて 6 MB ほど |
| 実装 | `back/src/common/error_log.rs`（`crate::elog!` は標準エラーとこのファイルの両方に書く） |

## 3. 手順

1. 不具合の問い合わせがあったら、設定の「情報」で場所を確かめ、`error.log`（と `error.log.1`…）を開く。
2. 日時で問題の起きたころを探す。

## 4. うまくいかないとき

| 症状 | 原因 | 対処 |
|---|---|---|
| `logs` フォルダが無い | まだエラーが 1 回も起きていない | - |
| 起動できないときのエラーが無い | ログはバックエンドが起動してから書く | デスクトップアプリは起動エラーの画面、共有サーバーは起動したターミナルの表示を見る |
